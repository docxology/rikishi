# Changelog

## 1.0.0 — release candidate, not yet published

This entry describes the planned first public release. A version number in source
or metadata does not establish a published GitHub release or a registered digital object identifier (DOI).
The release checklist records the actual artifact and publication identities.

### Added

- Worked numbers in prose and graphical abstracts drawn directly from the same
  witness, channel and simulation outputs as the tables and figures. Controls
  reject missing inputs, mismatched payloads and data that would make the
  stated witness comparisons false before figure export.

- A separate finite one-step action planner and `active-demo` command, with exact
  transition/observation laws, explicit outcome preferences, numerical information
  gain, checked score decomposition and all numerical ties. Modular guides
  distinguish its Active Inference role from fixed-observation inference,
  ontology alignment, the existing simulator and empirical claims.
- Pinned Suggested Upper Merged Ontology (SUMO) acquisition, complete source/formula inspection, provenance-aware
  indexing, taxonomy/navigation queries, and corpus measurements.
- Controlled source-kernel inference with E and Vampire, separate background,
  premise-removal, countermodel and refutation obligations, and retained replay.
- Shared rational finite witnesses connecting mathematical model,
  representation, calculation and result roles across SUMO questions,
  Python arithmetic and named Lean statements.
- Exact channels, observation degradation, evidence scaling, sequential
  conditioning, model-prior comparisons and an all-eight-history atlas.
- Restricted finite-event pullback/pushforward operations with separately scoped
  Lean obligations; no general source-translation soundness claim.
- Read-only web/Model Context Protocol (MCP) inspection, offline explorers and report-derived figures.
- A software-methods manuscript with three dense graphical abstracts on physical
  pages 2–4, source locators, explicit assumptions and mathematical examples.
- Modular installation, methods, application programming interface (API), reproduction, contribution, security,
  review and release documentation; synchronized citation/archive metadata.

### Verification and presentation

The release candidate retains real-file and subprocess controls, exact
source/artifact bindings, two branch-inclusive coverage floors, bounded Office
projections, actual embedded-image comparisons and complete visual inspection.
The native mutation fixture uses create-only APFS clones on supported macOS
filesystems and an explicit ordinary-copy path elsewhere, without silent fallback.

Actual pass counts, platform observations, artifact hashes and independent
verdicts belong to the completed release verification summary. Earlier builds
and interrupted checks do not transfer approval to a changed candidate.

### Limits

Finite calculations and named formal statements do not establish general SUMO
consistency, universal semantic preservation, independent proof authentication
or empirical/biological validity. Native platform, physical-device, accessibility
and publication limits remain explicit in the accompanying review record.
