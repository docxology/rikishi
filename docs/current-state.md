# Current release candidate and evidence

Rikishi is preparing its first public **1.0.0** release. Source metadata,
a staged archive, or a locally rendered Portable Document Format (PDF) does not establish a published
release or a passing qualification gate.

Use the [review guide](review.md) to identify the actual PDF and source.
The [release checklist](../RELEASE_CHECKLIST.md) records the required gates;
the [prioritized backlog](TODO.md) separates product, platform and research work.

## Implemented scope

| Layer | Implemented capability | Evidence boundary |
| --- | --- | --- |
| Source inspection | Pinned Suggested Upper Merged Ontology (SUMO) files, complete formula spans/hashes, indexes and graph/corpus queries | Parsing and asserted edges do not establish entailment or consistency. |
| Controlled inference | Explicit source kernels, local premises, E theorem prover and Vampire (E/V) commands, background/removal/refutation controls and replay | Results concern submitted problems, not all Sigma translations or authenticated proof objects. |
| Shared witnesses | Common rational prior/kernel/candidate inputs and model, representation, calculation and result identifiers | Shared labels do not prove semantic equivalence. |
| Finite mathematics | Exact channels, coarsening, evidence scaling, Boolean histories, next predictions and model priors | These are declared finite calculations, not empirical or biological validation. |
| Simulation | Seeded trajectories under explicit sampling assumptions | Simulated trajectories are not observations of a natural system. |
| Action planning | One-step transition/observation prediction, outcome preferences, risk/ambiguity/information gain, explicit numerical ties and filtering | Standalone finite decision method; no sampled environment loop, longer policy search, new Lean proof or native SUMO claim. |
| Lean | Named finite laws and restricted event-transport obligations with explicit hypotheses | No general SUMO-to-Lean soundness theorem is claimed. |
| Interfaces | Read-only Hypertext Transfer Protocol (HTTP)/Model Context Protocol (MCP) inspection, offline explorers and command-line interface (CLI) execution | This is not an authenticated multi-user network service. |
| Publication | A source/bibliography/data-bound producer, graphical abstracts and PDF/Office checks | Build, visual, editorial and release acceptance remain separate. |

## Qualify the particular artifact

The release verification summary must bind one exact source revision and file
inventory to actual test/coverage, package, native-edition and independent-review
records. Inspect the PDF hash, page count and source/version identity. A filename
or local output path does not certify freshness.

A successful complete gate requires every collected case with no failure,
error or skip, both branch-inclusive floors (90% core and 60% infrastructure),
and successful package builds. Portable-only, focused and interrupted runs retain
their narrower meanings. Earlier builds cannot qualify a changed release candidate.

PDF, Word, Hypertext Markup Language (HTML) and packages are generated artifacts. Their source/receipt
identities and distributable copies belong in the reviewed release bundle.
The wheel supplies the Python package; the source distribution supplies the
documented source/configuration/scripts. See [installation](installation.md).

## Explicit limits

Microsoft Word native pagination, physical print/phones, native zoom and
large text, full screen-reader/keyboard/clipboard operation, cold-offline loading,
transient UI states and hosted-platform qualification need their own actual
observations. Saved viewports or accessibility trees do not substitute for them.

Full-width prose, a fixed light publication surface and distinct scholarly
prose/interface/code roles are declared design choices. Generic checklist
departures and reviewer-specific limits stay attached to the exact artifact.

Shared witnesses, finite calculations, selected native results and named Lean
statements do not establish global ontology consistency, general semantic
preservation, independent proof authentication, biological validity or editorial
approval. Publication does not remove these limits.
