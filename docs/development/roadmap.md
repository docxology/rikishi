# Rikishi roadmap

Updated 2026-11-05 for the 1.1.0 candidate. The
[published 1.0.0 release](https://github.com/docxology/rikishi/releases/tag/v1.0.0)
retains its own source, artifacts and verification summary. Work below concerns
new source and future research; previous evidence does not qualify a changed
candidate. See [current methods](current-state.md) and the
[release checklist](../../RELEASE_CHECKLIST.md).

## Current release

- Freeze synchronized 1.1.0 package, study-authority and documentation inputs.
- Qualify the complete native suite with every collected case and the unchanged
  90% core and 60% infrastructure branch-inclusive coverage floors.
- Build and inspect packages, then test their supplied bytes in a clean environment.
- Regenerate all affected native campaigns, numerical reports and manuscript
  editions; inspect every physical Portable Document Format (PDF) page and figure.
- Retain independent review findings, dispositions, source and asset manifests,
  actual hosted portable checks, warnings and rejecting controls.
- Publish the new GitHub release and distinct Zenodo software/manuscript records;
  verify the actual landing pages, identifiers, licenses and downloaded bytes.
- Record verified publication identities and dates after they exist.

| Extend sequential uncertainty | Distinguish dependent observations within a trajectory from independent replicated paths and assess explicit alternative model assumptions. |

## Research extensions

| Work | Required result |
| --- | --- |
| Prove semantic transport for a stated source fragment | Define carriers, membership, formula/function interpretation, support and logarithms; prove an actual correspondence theorem and reject substantive false cases. Restricted finite-event proofs are a starting point. |
| Broaden ontology competency coverage | Review workbook senses, encodings and domain questions; state intended cache-inheritance semantics and test any complete-profile correction with fresh controls. |
| Authenticate proof production and proof steps | Add independent proof-object checks and trusted producer/dependency authentication beyond hashes, status text and portable replay. |
| Test empirical adequacy | Specify measurable hypotheses, observations, uncertainty, comparison models and domain review. Simulations and formal identities alone do not establish biological validity. |

No selected source kernel, finite calculation, named Lean statement or local
cache observation establishes whole-ontology consistency or general semantic
preservation. Keep those research questions open until their stated obligations
are met. Preserve all prior successful and failed evidence under its original
identity outside public installation inputs.
