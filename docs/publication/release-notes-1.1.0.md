# Rikishi 1.1.0

These notes describe the versioned source changes. The
[GitHub release](https://github.com/docxology/rikishi/releases/tag/v1.1.0), attached
verification summary and actual digital object identifier (DOI) landing pages
record publication and qualification. The existing
[1.0.0 release](https://github.com/docxology/rikishi/releases/tag/v1.0.0) and its
attached files remain intact.

## Changes

- Registered translated-background context requires the complete checksum-verified
  bytes; an unverified digest alone cannot select a known context.
- Capture inspection hashes and parses the capture record from one bounded
  snapshot, requires its retained report digest, and checksum-verifies referenced
  payloads when they are read.
- Native execution and replay share exact registered direct-prover options;
  an internally coherent capture with different options is rejected.
- The superseded manually seeded Java cache diagnostic and retired template
  copies are removed. Generated evidence is retained outside Git tracking.
- Finite Decimal calculations use explicit local arithmetic contexts so a caller's
  precision, rounding and traps cannot silently change reported values.
- Production Git subprocesses receive closed standard input.
- Documentation identifies published releases accurately and presents current
  methods separately from preserved development evidence.

The scientific populations and acceptance scopes remain explicit. Source
expressions, submitted native theorem-prover problems, exact finite arithmetic,
named Lean obligations and simulation results establish different claims.
See [current methods](../development/current-state.md) and [reproducibility](../methods/reproducibility.md).

## Qualification record

Before publication, the verification summary must record the exact candidate
commit and maintained-source inventory; complete native test, coverage and
package results; hosted portable checks; newly generated campaign and manuscript
identities; all-page inspection and independent review; and the final public
asset manifest. Preserve all warnings and failed controls with their actual
source and execution identities. A previous release's checks do not qualify
the changed source.

## Publication record

The intended objects are a new `v1.1.0` GitHub release and distinct versioned
Zenodo software and manuscript records. Software is MIT licensed; the original
manuscript and figures are CC BY 4.0, with third-party exceptions retained in
the notices and actual file inventory. Fill the release record with actual
public links, record identifiers, publication dates and independently verified
download digests only after those events occur. The cited alignment precedent
DOI does not identify Rikishi.

Microsoft Word and physical-device behavior, accessible-document operation,
whole-ontology consistency, general ontology-to-Lean preservation, authenticated
proof steps and empirical biological validity retain their stated limits.
